# Decisions (source of truth)

Settled in a grilling session on 2026-11-06. This file **overrides** `docs/brief.md` wherever they differ. The brief remains the original product intent and the phase outline. Read this file first in any new session.

## Situation (not derivable from code)

- Owner uses an **iPhone on iOS 26.6.2** and a **Windows PC**. There is **no Mac and no Xcode**.
- Free Apple ID only (no paid developer account). The free account has 3 active-app slots, and **AltStore plus another app the owner built already use them**. Anything needing an extra app ID (share extension, widgets) is out.
- Personal use, sideloaded via AltStore (re-signs every 7 days). No App Store, no store-policy work.
- Nothing exists yet except the brief, this file and `CLAUDE.md`. **Next step: Phase 0** (see below).

## Platform and stack

- iOS 26 only (deployment target iOS 26). Android is dropped.
- Native **Swift** with SwiftUI plus a UIKit `WKWebView` wrapper. No cross-platform framework.
- One WebView, **one tab** in the MVP. The data model must not preclude tabs later (session = list of tabs, length 1).
- Project generated by **XcodeGen** from a committed `project.yml` (no hand-made `.xcodeproj`).
- Build: a GitHub Actions macOS runner builds an **unsigned IPA** (`CODE_SIGNING_ALLOWED=NO`, zip `Payload/`). Signing and install happen on the owner's side through AltStore.
- Repo will be **public** so standard runners are free. Verify this against actual billing on the first run. If it turns out to cost money, revisit.
- **macOS runner minutes cost 10x.** See the CI rules in `CLAUDE.md`. They are mandatory.

## Testing without a Mac

Keep the Apple-only layer as thin as possible. Everything else runs on Windows or Linux.

- **Pure-Swift package** (watching state, history/queue logic, rule handling, allowlist, persistence): tested with the Swift toolchain on Windows. No Apple frameworks inside it.
- **Injected JS files** (video detection and control, cosmetic and scriptlet glue): plain JS files tested with Playwright's WebKit build on Windows.
- **Filter-list conversion** is checked in Node as a sanity test. The real conversion runs on the device.
- Only the thin WebView, PiP, audio-session and URL-scheme layer needs the runner plus the physical phone.

## Content blocking

- Engine: **AdGuard's Swift converter (SafariConverterLib)** turns list text into Safari content-rule JSON, compiled to `WKContentRuleList` on the device. Cosmetic filters and scriptlets (AdGuard Scriptlets) are injected as user scripts. **No home-grown engine.**
- Why on the device: the brief requires in-app list auto-update.
- Default lists: EasyList, EasyPrivacy, AdGuard Mobile Ads. Respect the rule-count cap per list by splitting into several lists.
- Update: on app launch if the lists are more than 24 hours old, plus a manual "Update now" button. No background refresh.
- On download or compile failure: keep the last good compiled lists and show an error. Never end up with no blocking.
- Custom rules: free-text lines in ABP/AdGuard syntax, compiled into their own list.
- Allowlist and per-site disable: remove the rule lists and scripts for that host, then reload the page.
- **No blocking statistics** (iOS gives no blocked-request count). Post-MVP.
- Accepted limitation: weaker than desktop uBlock (no per-request hooks, rule cap).
- Only list downloads leave the device. Document this.

## Video

- Scope: any HTML5 `<video>` on any site, including iframes and blob/MSE streams. **DRM sites are out.** Find incompatible sites empirically and list them in `docs/incompatible-sites.md`. No per-site extractors.
- **Fail open:** if video mode can't engage (DRM, no controllable element), the page behaves as a plain browser and the video-mode button is disabled.
- **Own fullscreen**, not the native iOS fullscreen player: rotate the app to landscape and expand the page's `<video>` with CSS. Custom controls and gestures sit on top. PiP uses the video element's presentation mode.
- **Entry:** tapping the page's fullscreen button (intercepted) or tapping our floating button, which appears once a primary video is detected.
- **Lock:** while in video mode, main-frame navigation and popups are cancelled. Exit through an explicit back control that returns to the same page and position.
- **Gestures:** horizontal drag seeks. Vertical drag on the left half sets brightness (`UIScreen.brightness`). Vertical drag on the right half sets volume through a hidden `MPVolumeView` slider (**fragile workaround, mark it so in code**). Double-tap seeks 10 seconds backward or forward. Long-press plays at 2x. A single tap toggles the controls.
- **PiP and background playback are in the MVP** (audio background mode, audio session, media session, now-playing info).
- Autoplay without a tap is allowed (`mediaTypesRequiringUserActionForPlayback = []`), so the queue can auto-advance.

## JS bridge and security

- Injected scripts that talk to native (video detection, controls, the message bridge) run in an **isolated `WKContentWorld`**, in all frames.
- **Exception (decided 2026-11-06):** the AdGuard cosmetic and scriptlet bundle runs in the **page world**, because scriptlets patch page APIs. It has **no message handler**, so the page gets no path to native code through it.
- Native accepts a small fixed set of messages with a schema and validation. No general-purpose bridge.
- Treat page content as untrusted. Use the default iOS file protection. Data stays local.

## Browsing defaults

- Non-URL text in the address bar opens a configurable search-URL template (DuckDuckGo default). This is not a built-in search engine.
- Cookies and logins persist in the default WebKit data store. Settings has a "Clear website data" button.
- `target=_blank` and `window.open` load in the same view.

## Persistence and library

- **SQLite via GRDB**, pure Swift, so it is testable on Windows. No SwiftData or Core Data.
- **Video identity:** canonical page URL (tracking parameters stripped) plus the video's index among the page's videos. Single-page sites change the URL without a reload, so the detector listens for URL changes. Resume sets the position once the video's metadata has loaded.
- **Continue Watching:** past roughly 15 seconds and not within the last few percent of the duration. Live streams (no duration) are excluded. The thresholds are constants and may be tuned later.
- **History** auto-deletes after 90 days. **Continue Watching** entries go when the video is marked complete or after 60 days untouched. **Watch Later** is never auto-deleted.
- **Queue:** an ordered list of page URLs. When a video ends, navigate to the next one and enter video mode.
- **Relaunch:** reopen the last URL and show a "Resume where you left off" banner. Nothing auto-plays until the user taps it.

## App layout

- The browser is the home screen. **Library** (Continue Watching, Watch Later, History, Queue) and **Settings** are sheets opened from the bottom toolbar. Video mode is a full-screen cover over the browser.

## Sharing and links

- **No share extension, no universal links** (they would need extra app IDs or a paid account).
- Primary path: custom URL scheme `nullview://open?url=…`, plus a Shortcuts-app shortcut in the share sheet that opens that URL.
- Backup: detect a URL on the clipboard at app launch.
- Deep links use the custom scheme only.

## MVP (replaces brief section 21)

Included: WebView, basic navigation, real blocking with filter lists, allowlist and custom rules, video detection, dedicated video mode, fullscreen, **PiP, background playback**, playback position, Continue Watching, basic history, URL-scheme and clipboard sharing.

Excluded: blocking stats, share extension, universal links, tabs, DRM sites, everything in the brief's non-goals.

## Phase 0 (hard gate, stop rule)

Do not build the app before all five pass. If any fails, **stop and re-decide with the owner**. Do not silently fall back to a home-grown blocker or to a weaker design.

1. Real filter lists (EasyList, EasyPrivacy) compile to content-rule lists and block known ad requests on a test site, within the rule cap.
2. Scriptlets and cosmetic filters run through injected user scripts.
3. PiP works on a custom-controlled video.
4. Audio keeps playing after the screen locks or the user switches apps.
5. The Shortcut opens the app with a URL through `nullview://`.

Phase 0 is also the first test of the whole pipeline: XcodeGen, an unsigned IPA from CI, AltStore install, and an actual run on the phone.

## Unverified assumptions (check early, don't trust)

- Public-repo macOS runners are free (billing).
- AltStore's handling of the free-account app-ID limit, and whether a URL scheme needs nothing extra.
- That `MPVolumeView` volume control still works on iOS 26.
- ~~That the AdGuard converter builds with the Swift toolchain on Windows.~~ **Checked 2026-11-06 (Swift 6.4.2, v4.3.1): partly.** The `ContentBlockerConverter` module (list text to Safari JSON) compiles on Windows. The `FilterEngine` module (`WebExtension`, cosmetic/scriptlet lookup) does **not**, because it uses POSIX `flock`. So the pure-Swift package may depend on `ContentBlockerConverter` but must keep `FilterEngine` behind a protocol and out of Windows tests. Windows build quirks: clone with `core.autocrlf=false` (the version plugin fails on CRLF), and the plugin needs `/usr/bin/true` with the native build system (we stubbed it in a throwaway clone). The plain `swift build` default build system fails to find MSVC headers in this shell.
- Whether `requestFullscreen` interception works reliably inside `WKWebView` on iOS 26.
